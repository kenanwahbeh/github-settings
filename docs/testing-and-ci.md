# الاختبارات وCI

شغّل أصغر مجموعة فحوص مناسبة للتغيير ثم وسّعها حسب الوقت والمخاطر. اذكر فقط ما شغّلته فعلياً.

## أنواع الفحوص
1. اختبارات الوحدة لقواعد الأعمال والحسابات.
2. اختبارات التكامل لقواعد البيانات وواجهات API والخدمات.
3. اختبارات المسارات الأساسية من البداية للنهاية.
4. lint وفحص الأنواع والتحليل الأمني.

اختبر النجاح والفشل والحالات الطرفية والصلاحيات ذات الصلة. لا تضف اختبارات شكلية لا تتحقق من سلوك مهم.

## Python
افحص المشروع أولاً واستخدم الأدوات الموجودة. أمثلة شائعة وليست إلزامية:
```bash
pytest
pytest --cov
ruff check .
ruff format --check .
mypy .
bandit -r .
```
لا تفترض وجود مجلد `src` أو إعدادات تغطية أو mypy قبل التحقق.

## JavaScript/TypeScript
افحص `package.json` أولاً؛ قد تتوفر scripts مثل:
```bash
npm test
npm run lint
npm run typecheck
npm audit
```
لا تفترض أن هذه scripts موجودة.

## فحوص هذا المستودع (موجودة فعلاً)
```bash
uv run --with pyyaml python tests/test_apply.py     # اختبارات apply.py — بلا شبكة
bash scripts/check-workflows-sync.sh                # workflows/ == .github/workflows/
bash scripts/check-tool-versions.sh                 # إصدارات الأدوات داخل shell تطابق scripts/tool-versions.cfg
```

## GitHub Actions
- استخدم أقل صلاحيات لازمة، وأسماء checks ثابتة.
- شغّل الاختبارات على Pull Requests والفرع الافتراضي.
- لا تضع أسراراً في workflow ولا تمرر مدخلات غير موثوقة إلى shell مباشرة.
- راجع إصدارات Actions وتحديثاتها.
- قواعد حماية الفرع يجب أن تشير إلى check يظهر فعلاً في CI.

## التقرير
ميّز بوضوح بين: نجح، فشل، لم يُشغّل، وغير منطبق. إذا تعذّر الاختبار بسبب بيئة أو اعتماديات، اذكر السبب ولا تصف المهمة بأنها مختبرة بالكامل. التغطية لا تساوي جودة الاختبارات.
