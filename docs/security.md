# خط أساس الأمان

هذه قائمة مراجعة أولية وليست ضماناً لخلو التطبيق من الثغرات.

## الأسرار
- لا تحفظ API keys أو كلمات المرور أو tokens أو ملفات البيئة الحقيقية في Git.
- استخدم مخزن أسرار أو متغيرات بيئة مناسبة، ولا تطبع الأسرار في logs أو prompts.
- عند تسريب سر، أبطله أو دوّره أولاً؛ حذف الملف وحده لا يزيله من تاريخ Git.
- استخدم Gitleaks لفحص الأسرار، بما فيها التاريخ عند الاشتباه بتسريب.

## الهوية والصلاحيات
- تحقق من الهوية والتفويض على الخادم لكل مورد حساس؛ إخفاء زر في الواجهة ليس تفويضاً.
- امنح أقل صلاحية لازمة للمستخدمين وGitHub Actions والتكاملات.
- استخدم مكتبات موثوقة لتخزين كلمات المرور والجلسات، مع حماية CSRF عند انطباقها.
- ضع حدوداً للمحاولات على مسارات تسجيل الدخول والعمليات الحساسة عند الحاجة.

## المدخلات والواجهات
- استخدم معاملات SQL، وتجنب shell أو HTML أو قوالب مبنية من مدخلات غير موثوقة.
- تحقق من المدخلات وقيّد رفع الملفات بالحجم والنوع والمكان.
- استخدم HTTPS في الإنتاج، وضيّق CORS، ولا تعتبره بديلاً عن المصادقة.
- لا تكشف stack traces أو تفاصيل داخلية في أخطاء الإنتاج.
- راجع مخاطر SQL injection وXSS وSSRF وحقن الأوامر حسب مسارات التطبيق الفعلية.

## الاعتماديات وCI
- فعّل Dependabot alerts وsecurity updates، واستخدم Gitleaks وSemgrep عند ملاءمتهما.
- استخدم `permissions: contents: read` افتراضياً في workflows وارفع الصلاحيات عند الحاجة فقط.
- تجنّب `pull_request_target` مع كود غير موثوق ما لم يوجد تصميم أمني مدروس.
- راجع مصدر GitHub Actions ونسخها؛ لا تتجاهل تنبيهاً قبل فهمه.
- لا تنفّذ أوامر مدمّرة أو تغيّر بيانات إنتاجية خلال الفحص دون موافقة.

## مراجعة قبل النشر
راجع الأسرار، الصلاحيات، الإعدادات الإنتاجية، النسخ الاحتياطية، migrations وخطة التراجع. أدوات التحليل الساكن تساعد لكنها لا تثبت أن التطبيق آمن.


## سلامة وضع المعاينة في أداة apply.py
- يجب أن يتحقق التطبيق من أن قيمة المستودع هي `owner/repository` فقط قبل تركيب مسارات API، وألا يسمح بتمرير معاملات URL أو مسارات إضافية.
- في `--dry-run` تُنفَّذ قراءات API اللازمة لبناء معاينة صحيحة، لكن لا يجوز تنفيذ أي طريقة HTTP غير آمنة. تُعامل الطرق غير المعروفة وخيار `-X` الناقص كعمليات كتابة وتُحجب.
- اختبر هذه الحدود باختبارات وحدة دون اتصال، ولا تستخدم صلاحيات حقيقية أو بيانات إنتاجية في الاختبارات.
