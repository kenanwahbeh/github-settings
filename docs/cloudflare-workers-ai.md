# Cloudflare Workers AI ووكيل البرمجة

## افصل بين النموذج والوكيل
Workers AI يوفر تشغيل نماذج مستضافة، لكنه لا يشكّل وحده وكيل برمجة متكاملاً. يحتاج الحل عادةً إلى:
1. نموذج لغوي لتفسير الطلب واقتراح التغييرات.
2. منسّق يدير السياق والخطوات واستدعاءات الأدوات والأخطاء.
3. أدوات محددة لقراءة ملفات GitHub والبحث وإنشاء فرع أو Pull Request.
4. بيئة منفصلة لتشغيل الاختبارات والفحوص، مثل GitHub Actions.
5. موافقة المستخدم قبل الدمج أو النشر أو العمليات عالية الأثر.

## بنية أولية آمنة
- ابدأ بوضع القراءة والتقرير، ثم اسمح بإنشاء فرع وPull Request.
- استخدم GitHub App أو token محدوداً بمستودعات وصلاحيات محددة.
- خزّن الأسرار في مخزن أسرار، لا في الكود أو prompt أو logs.
- استخدم قائمة سماح للأدوات والمدخلات؛ لا تنفذ أوامر shell عشوائية مولّدة من النموذج.
- شغّل الاختبارات الثقيلة في CI بدلاً من افتراض أن Worker بيئة بناء عامة.
- تعامل مع محتوى الملفات وIssues وPRs كمدخلات غير موثوقة قد تحتوي تعليمات خبيثة.
- لا تسمح بالدمج أو النشر التلقائي قبل وضع سياسة موافقات وفحوص موثوقة.

## دورة العمل المقترحة
1. تحديد المستودع والفرع والهدف.
2. جمع أقل سياق لازم من README والملفات ذات الصلة.
3. إعداد خطة قصيرة مرتبطة بملفات محددة.
4. التحقق من الصلاحيات قبل كل إجراء.
5. إجراء التعديل في فرع مستقل.
6. تشغيل الاختبارات وlint وفحوص الأمان المناسبة.
7. مراجعة diff والتأكد من تطابقه مع الطلب.
8. فتح PR يتضمن ملخصاً ونتائج الفحوص.
9. انتظار موافقة صريحة للدمج والنشر.

## حدود يجب التحقق منها
النماذج المتاحة والحصص والأسعار وحدود الطلبات تتغير؛ راجع التوثيق الحالي قبل التصميم. اختيار النموذج لا يضمن جودة التعديل، ويجب التحقق من كل إجراء ونتيجته. هذه الوثيقة اقتراح معماري وليست ادعاءً بأن تكاملاً قد نُشر بالفعل.
